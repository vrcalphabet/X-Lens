# X-Lens Studio 🔍

X.com（旧Twitter）に投稿された画像の上に「仮想の虫眼鏡」を重ねると、虫眼鏡越しに**フルカラーの別の画像（裏画像）**が浮かび上がるステガノグラフィー変換＆プレビューシステムです。

PCブラウザからの投稿に特化しています。**どの画像も長辺896pxに高画質縮小（[pica](https://github.com/nodeca/pica)）してから、裏画像をJPEGに圧縮して表画像の最下位ビットに埋め込みます。** X は896px以下で透過ピクセルを含むPNGを変換せずに配信するため、表画像をほとんど変えずに、裏画像を等倍の解像度で届けられます。

---

## 1. システムのコア技術・アルゴリズム

### ① LSB無劣化埋め込み

X上で `896×896` の透過PNGがピクセル単位で完全一致のまま配信されることを実投稿で確認したため（ffmpeg PSNR = inf）、すべての画像を長辺896pxに縮小してから **LSB方式** で埋め込みます（[`src/core/codec.js`](src/core/codec.js)）。

- 縮小は pica（MKS2013フィルタ、Web Worker／WASMで実行）で行います。ブラウザだけで動くので、サーバーは不要です。「切り抜く」では元の解像度のまま中央を切り抜いてから縮小し、「全体を入れる」では縮小した画像を背景色の中央に置きます
- 小さい画像は長辺896pxに拡大されます
- 届くビットは1つも変わらないので、裏画像は**生の画素ではなく、等倍のJPEGファイルとして**入れます（品質0.95。入りきらないときだけ品質を下げます）
- 表画像は R・G・B の最下位1bitだけを使います（各チャンネル最大±1）。ラスター順に、先頭から必要な分だけ書き、残りは元のままです
- 先頭20バイトはヘッダ `['X','L', 2, mode=2, minLensPct, maxLensPct, width, height, JPEGの長さ, CRC-32, CRC-16]` です。虫眼鏡のサイズ範囲もここに入ります
- 容量は (幅×高さ−1)×3bit（896×896で約294KB）。写真のJPEGは多くの場合50〜120KBです
- 1bitでも壊れるとCRC-32で検出し、「裏画像なし」として扱います
- JPEGに変換されるとLSBは全滅します（ヘッダ未検出になります）

シミュレーションでの測定（サンプル画像、表の変化は存在マークを除いた埋め込みだけの分）:

| 出力                      | 表画像PSNR（旧1/2解像度方式→現方式） | 裏画像PSNR（旧1/2解像度方式→現方式） |
| :------------------------ | :----------------------------------- | :----------------------------------- |
| 896×896（りんご／バナナ） | 46.4 → 56.7 dB                       | 46.8 → 49.3 dB                       |
| 600×896（人物／ピエロ）   | 46.5 → 54.7 dB                       | 35.3 → 37.8 dB                       |
| 896×504（スカイツリー）   | 46.4 → 57.7 dB                       | 34.0 → 50.3 dB                       |

### ② 存在マーク（縮小・JPEGに強い「X-Lens画像かどうか」の目印）

タイムラインの縮小版（`name=small` など）から、`name=orig` を取得せずにX-Lens画像かどうかを判定するための目印です（[`src/core/mark.js`](src/core/mark.js)）。エンコード前の表画像に加えます。

- 画像を正規化座標で **96×96マス** に分け、固定の疑似乱数パターン（各マス ±1）に従って、各マスになめらかな明るさの山（`sin` 窓、マスの境目で0）を足します。マスは縦横比に合わせて伸びるので、どのサイズに縮小されても格子が崩れません
- 山の高さは周りの模様の細かさに合わせて **±1.5〜4階調**（平坦な所ほど弱く）
- 252〜255（と0〜3）の値はLSB処理で同じ値に潰れてマークが消えるため、端だけ軽く圧縮します（255→252、0→3。6〜249は不変）
- 判定：どのサイズでも288×288に面積平均で縮め、細かいハイパスで絵柄の陰影を除いてから、マスごとにパターンとの相関を取ります。スコアは z 値（マークなし画像では標準正規分布に近い）で、**z ≥ 6 で「マークあり」**
- 入れられる情報は「X-Lens画像かどうか」の1ビットだけです。虫眼鏡のサイズ設定と裏画像は、これまでどおり `name=orig` から読みます

シミュレーションでの測定（scikit-imageの写真21枚、縮小はlanczos3、JPEGはlibjpeg 4:2:0）:

| 出力        | 表画像PSNR（マークなし→あり） | 680px・JPEG Q85 での z（最小／平均） | 360px・Q75 |
| :---------- | :---------------------------- | :----------------------------------- | :--------- |
| 896×896 LSB | 45.8 → 41.6 dB                | 11.5 / 35.9（21/21検出）             | 21/21      |
| 896×560 LSB | 45.9 → 41.7 dB                | 10.0 / 35.7（21/21）                 | 21/21      |

マークなし画像714枚（マークなしでエンコードしたX-Lens画像、元写真の各サイズ・反転）では z の標準偏差 0.94、最大 |z| 2.9 で、誤検知は0件でした。短辺が192px未満の画像は判定しません。裏画像の復元には影響しません。Xの実際の縮小処理とは異なるため、実投稿での確認はまだです。

### 合言葉（任意）

作る画面で合言葉を入れると、裏画像のJPEGをAES-256-GCMで暗号化してから埋め込みます（鍵は合言葉からPBKDF2-SHA256・60万回で作成、saltとIVは画像に格納）。合言葉が違うと必ず検出できます。存在マークは別の乱数パターンになるので、縮小版からでも「鍵付き」かどうかが分かります。サーバーはなく、合言葉を知った人が他の人に教えることは防げません。

### ③ 端1px 透過PNGトリック (`Alpha = 254`)

- 出力PNG画像の右下1ピクセルのみ `Alpha = 254`（不透明度99.6%）に設定します。
- X.comのPCブラウザ投稿仕様上、`900 × 900 px` 以下（本システムでは長辺 **896px**）かつ透過ピクセルを含むPNGは、サーバー側でのJPEG変換がスキップされ **100%無劣化のPNG** として保存・配信されます。

## 2. 開発の始め方

Node.js 20.19 以上（または 22.12 以上）が必要です。

```sh
npm install      # 初回だけ
npm run dev      # 開発サーバー http://localhost:8192 （保存すると即反映）
npm run build    # 公開用のファイルを dist/ に作る
npm run preview  # dist/ をローカルで確認（アプリとしてのインストール・オフライン動作もここで確認）
```

### 拡張機能（Chrome / Edge）

拡張機能は [CRXJS](https://crxjs.dev/)（Viteプラグイン）でビルドします。

```sh
npm run dev:ext    # 開発用。保存すると拡張機能に即反映（HMR）。http://localhost:5174 を使います
npm run build:ext  # 公開用のファイルを extension/dist/ に作る
```

`chrome://extensions`（Edge は `edge://extensions`）で「デベロッパーモード」をオンにし、「パッケージ化されていない拡張機能を読み込む」で `extension/dist` を選びます。

- `npm run dev:ext` の間は、コードを保存するだけで拡張機能とXのタブに反映されます（開発サーバーを止めると動かなくなるので、普段使いは `build:ext` の結果を読み込んでください）
- `npm run build:ext` のあとは、拡張機能の更新ボタンを押し、Xのタブを再読み込みします
- manifest は `extension/manifest.config.js` に書きます。ビルド時に `extension/dist/manifest.json` が作られます

- 右下（Grok／チャットの上）の丸いボタンでレンズモードをオン／オフします（状態は保存せず、タブごと。ページを読み込むたびにオフから始まります）
- ホイールで変えたレンズの大きさは画像ごとに覚えておき、一度カーソルを外しても同じ大きさで出ます（読み込み直すとリセット）
- レンズモード中だけ、画面に入った投稿画像の縮小版（`name=small` など、表示中のもの）で存在マークを判定し、X-Lens画像に金色の枠を付けます
- 金色の画像にマウスを乗せると `name=orig` を取得して裏画像を復元し、レンズで表示します。ホイールでレンズの大きさを変えられます（作成者が決めた範囲内）
- 合言葉付きの画像は紫色の枠になります。マウスを乗せるとレンズに鍵が表示され、クリックすると合言葉入力のポップアップが出ます。解除できた合言葉はポストIDと画像番号（1〜4）ごとに `chrome.storage.local` に保存され、次からは金色の枠で、入力なしで見られます
- レンズの大きさが固定されている画像（作成者が最小と最大を同じにした場合、読み込み中・鍵付きの表示中）の上では、ホイールでタイムラインをスクロールできます
- 右クリックメニュー：レンズモードがオフのときは、Xの画像の右クリックメニューに「拡大画像をコピーする」が加わります（元のサイズの画像をコピー）。オンのときは、X-Lens画像の右クリックで独自のメニューが開き、「表画像をコピーする」「裏画像をコピーする」を選べます（合言葉付きで未解除なら裏画像はグレーアウト）
- 画像を大きく表示した画面（`/photo/N`）ではボタンを出しません。先にレンズモードをオンにしてから開いてください
- 画像はまずページから取得し（Xが表示済みの画像と同じキャッシュを使う）、CORSで断られたときだけService Workerが取得します。どちらで取得したかはDevToolsのコンソール（詳細レベル）に `[X-Lens]` と表示されます
- 権限は `storage`、`contextMenus` と `https://pbs.twimg.com/*` だけです

公開は `dist/` の中身を静的ホスティング（GitHub Pages、Cloudflare Pages など。HTTPS必須）に置くだけです。サーバー側の処理はありません。

使っているライブラリ:

| ライブラリ                                                        | 用途                                       |
| :---------------------------------------------------------------- | :----------------------------------------- |
| [Vite](https://vite.dev/) 8                                       | 開発サーバーとビルド                       |
| [Tailwind CSS](https://tailwindcss.com/) 4（`@tailwindcss/vite`） | スタイル                                   |
| [pica](https://github.com/nodeca/pica) 10                         | 896pxへの高画質縮小                        |
| [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) 2（Workbox） | アプリとしてのインストールとオフライン動作 |

## 3. ファイル構成

```
index.html            画面のHTML（Tailwindのユーティリティクラスで見た目を指定）
vite.config.js        Vite・Tailwind・PWA（アプリ名、アイコン、キャッシュ）の設定
public/               そのまま配信するファイル
  favicon.png
  icons/              アプリ用アイコン（192px・512px）
  samples/            サンプル画像
src/
  main.js             画面の制御（ルーティング、各画面、縮小、保存、貼り付け）
  samples.js          サンプル画像ペアの読み込み
  styles/app.css      デザイントークン（@theme）と、ユーティリティで書きにくい部品
  core/               画像処理（DOMに依存しないので、拡張機能からもそのまま使える）
    codec.js          LSB方式の埋め込み・ヘッダ検出・復元
    mark.js           存在マークの埋め込み・判定
  ui/
    lens.js           虫眼鏡ビュー（マウス追従、タッチ操作、比較スライダー）
extension/            Chrome拡張機能（src/core/ を共有）
  vite.config.js      拡張機能用のVite設定（CRXJS）
  manifest.config.js  manifest（CRXJSが読み、dist/manifest.json を作る）
  popup.html          ツールバーのポップアップ（アプリで開く、FAQ、利用規約、プライバシーポリシー）
  public/icons/       アイコン（そのままコピー）
  src/
    content.js        x.com上の処理（ボタン、存在マークの判定、金色の枠、レンズ）
    background.js     Service Worker（CORSで取得できないときだけ画像を取得）
```

- 画面は3つです。`#/` ホーム（虫眼鏡のデモ）、`#/make` 作る（画像選択 → 調整して保存。保存／コピー後に投稿方法のポップアップ）、`#/peek` 覗く（保存した画像の確認）
- 色・フォント・文字サイズ・ブレークポイントは `src/styles/app.css` の `@theme` にまとめています。`bg-graphite`、`text-ink-soft`、`max-narrow:`（幅760px以下）、`max-mid:`（幅960px以下）のように使えます
- 画面全体の大きさは `html` の `font-size` で決まります（幅1280px以下で1倍、1920px以上で1.5倍）。サイズはすべて rem なので、この1か所で全体が拡大縮小します
- アプリとしてのキャッシュは、ビルドしたファイルから自動で作られます（ファイルを増やしても設定の変更は不要）。開発サーバーでは無効です
